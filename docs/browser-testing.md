# 실제 UI 검증과 npmx 패턴 적용

npmx에서 참고한 목록·캐시·탐색·검증 방식을 Keundal의 대화 화면과 실행 방식에 맞춰 적용했다. 아래 내용은 구현 범위와 재현 방법을 설명한다. 성능 개선 수치를 측정한 결과는 아니다.

## 적용 범위

| 참고한 방식               | Keundal에 적용한 내용                                                                                                                            | 범위와 제한                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 작은 목록 응답            | `listSummaries()`가 대화 ID·제목·생성 시각만 반환한다. HTTP 호스트는 명시한 상태 필드의 원시 값만 선택한다.                                      | 기존 `list()`는 전체 기록을 반환한다. 저장소는 아직 전체 스냅숏을 읽으며, 이전 호스트는 요약 쿼리를 무시할 수 있다.                                |
| 점진적 표시               | 사이드바·기록 화면·대화 본문을 나눠 표시하고 버튼으로 더 불러온다. 모델 목록은 공급자별 응답이 도착하는 대로 표시한다.                           | 본문 표시 범위만 제한한다. 모델 입력·편집·분기·내보내기에는 전체 기록을 유지한다.                                                                  |
| 캐시 수명 관리            | 모델 목록은 인증 설정별로 구분하고, 조회 실패 시 같은 설정의 캐시를 최대 24시간까지 재사용한다. 늦게 끝난 이전 요청은 새 캐시를 덮어쓰지 않는다. | 대화 응답에는 `private, no-store`를 지정한다. 개인별 클라이언트 상태를 공유할 위험이 있어 SSR payload 공유 캐시나 CDN 응답 캐시는 도입하지 않았다. |
| URL에 탐색 상태 보존      | `/history`의 검색어 `q`와 정렬 `sort`를 URL에 저장한다.                                                                                          | URL에 넣은 검색어는 브라우저 기록에 남을 수 있다. 기록 화면은 현재 저장소의 대화 요약을 검색한다.                                                  |
| 문맥에 맞는 명령          | 명령 팔레트에서 기록·설정으로 이동하고 현재 대화의 이름 변경·삭제를 실행한다.                                                                    | 이름 변경·삭제는 기존 동작과 확인 절차를 사용한다.                                                                                                 |
| 직접 연결과 기본 API 활용 | 메시지 위치 링크와 Markdown 내보내기를 제공한다. 클립보드와 파일 다운로드에는 브라우저 API를 사용한다.                                           | 메시지 링크는 해당 대화에 접근할 수 있는 환경에서만 유효하며 공개 공유 권한을 만들지 않는다.                                                       |
| 재현 가능한 검증          | UI는 실제 앱에서 직접 조작해 확인하고, 저장소 계약에는 속성 기반 검사를 사용한다.                                                                | UI 검증 결과와 확인하지 못한 항목은 PR에 기록한다.                                                                                                 |

목록은 버튼으로 표시 범위를 늘리는 방식을 택했다. 키보드 탐색과 스크린 리더가 사용하는 일반 목록 구조를 유지하고, 사용자가 연 이전 메시지나 편집기가 새 응답 때문에 사라지지 않도록 한다. 화면 밖 항목을 계속 제거하는 가상 목록이나 서버 저장소의 커서 기반 페이지 조회는 이번 범위에 포함하지 않았다.

## UI 검증 원칙

UI 테스트는 테스트 코드가 아니라 실행 중인 실제 앱의 화면을 직접 조작하여 진행한다. 브라우저 E2E, 컴포넌트 렌더링, HTML 문자열 비교, 시각적 스냅숏 테스트와 UI 전용 CI 검사는 추가하지 않는다. 서비스 계약·저장소·실행 제어·데이터 변환처럼 화면 렌더링과 무관한 단위·통합 테스트는 유지한다.

## 실제 앱에서 확인할 항목

변경 범위에 맞게 web 또는 desktop 앱을 실행하고 다음 항목을 확인한다.

- 변경한 사용자 흐름을 처음부터 끝까지 조작한다. 탐색, 입력, 저장, 취소, 새로고침 후 복원 결과를 확인한다.
- 메뉴·모달·편집·오류·빈 화면·로딩·스트리밍 등 영향을 받는 상태를 연다. 긴 대화, 첨부, 도구 결과와 출처가 관련되면 해당 데이터로 확인한다.
- 키보드 탐색, 포커스 이동과 복귀, 접근 가능한 이름, 스크린 리더 전달 내용을 확인한다.
- 밝은·어두운 테마, 좁은·넓은 화면, 언어 설정을 변경 범위에 맞게 확인한다. 터치나 desktop 네이티브 동작은 해당 입력 방식이나 실제 앱에서 확인하고, 브라우저 에뮬레이션과 구분해 기록한다.
- 개발자 도구에서 콘솔 오류, hydration 경고, CSP 위반과 의도하지 않은 외부 요청을 확인한다.
- Markdown과 출처를 변경하면 정상 콘텐츠뿐 아니라 안전하지 않은 URL·HTML, 스트리밍과 저장 후 복원도 확인한다.

웹 앱은 `features.inlineStyles: false`로 공통 CSS를 HTML에서 분리한다. 해시가 붙은 정적 CSS는 압축하고 캐시하므로 페이지마다 같은 스타일을 HTML로 다시 전송하지 않는다. 스타일 적용과 레이아웃은 실제 브라우저 화면에서 확인한다.

## 결과 기록

PR의 검증 사항에 실행 환경, 확인한 화면과 상태, 조작 순서, 기대 결과와 실제 결과를 기록한다. 필요한 스크린샷이나 상호작용 녹화를 첨부하고, 확인하지 못한 항목과 이유를 명시한다. 이 문서의 목록은 확인 절차이지 모든 화면이 검증되었다는 뜻은 아니다.

전체 단위·통합 테스트, 타입 검사와 린트는 기존 `pnpm test`, `pnpm typecheck`, `pnpm lint`로 별도 실행한다. 이 검사들의 통과를 실제 UI 검증으로 대신하지 않는다.
