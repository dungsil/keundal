# 브라우저 검사와 npmx 패턴 적용

npmx에서 참고한 목록·캐시·탐색·검증 방식을 Keundal의 대화 화면과 실행 방식에 맞춰 적용했다. 아래 내용은 구현 범위와 재현 방법을 설명한다. 성능 개선 수치를 측정한 결과는 아니다.

## 적용 범위

| 참고한 방식               | Keundal에 적용한 내용                                                                                                                            | 범위와 제한                                                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 작은 목록 응답            | `listSummaries()`가 대화 ID·제목·생성 시각만 반환한다. HTTP 호스트는 명시한 상태 필드의 원시 값만 선택한다.                                      | 기존 `list()`는 전체 기록을 반환한다. 저장소는 아직 전체 스냅숏을 읽으며, 이전 호스트는 요약 쿼리를 무시할 수 있다.                                |
| 점진적 표시               | 사이드바·기록 화면·대화 본문을 나눠 표시하고 버튼으로 더 불러온다. 모델 목록은 공급자별 응답이 도착하는 대로 표시한다.                           | 본문 표시 범위만 제한한다. 모델 입력·편집·분기·내보내기에는 전체 기록을 유지한다.                                                                  |
| 캐시 수명 관리            | 모델 목록은 인증 설정별로 구분하고, 조회 실패 시 같은 설정의 캐시를 최대 24시간까지 재사용한다. 늦게 끝난 이전 요청은 새 캐시를 덮어쓰지 않는다. | 대화 응답에는 `private, no-store`를 지정한다. 개인별 클라이언트 상태를 공유할 위험이 있어 SSR payload 공유 캐시나 CDN 응답 캐시는 도입하지 않았다. |
| URL에 탐색 상태 보존      | `/history`의 검색어 `q`와 정렬 `sort`를 URL에 저장한다.                                                                                          | URL에 넣은 검색어는 브라우저 기록에 남을 수 있다. 기록 화면은 현재 저장소의 대화 요약을 검색한다.                                                  |
| 문맥에 맞는 명령          | 명령 팔레트에서 기록·설정으로 이동하고 현재 대화의 이름 변경·삭제를 실행한다.                                                                    | 이름 변경·삭제는 기존 동작과 확인 절차를 사용한다.                                                                                                 |
| 직접 연결과 기본 API 활용 | 메시지 위치 링크와 Markdown 내보내기를 제공한다. 클립보드와 파일 다운로드에는 브라우저 API를 사용한다.                                           | 메시지 링크는 해당 대화에 접근할 수 있는 환경에서만 유효하며 공개 공유 권한을 만들지 않는다.                                                       |
| 재현 가능한 검증          | 브라우저 오류·CSP·외부 요청·접근성·사용자 설정 복원·긴 대화를 검사하고, 저장소 계약에는 속성 기반 검사를 추가했다.                               | 아래에 실행 범위와 제외 항목을 별도로 기록한다.                                                                                                    |

목록은 버튼으로 표시 범위를 늘리는 방식을 택했다. 키보드 탐색과 스크린 리더가 사용하는 일반 목록 구조를 유지하고, 사용자가 연 이전 메시지나 편집기가 새 응답 때문에 사라지지 않도록 한다. 화면 밖 항목을 계속 제거하는 가상 목록이나 서버 저장소의 커서 기반 페이지 조회는 이번 범위에 포함하지 않았다.

## 기능·접근성 검사 실행

저장소 루트에서 실행한다. Playwright가 `127.0.0.1:3100`에 프로덕션 Node 서버를 시작하므로 같은 포트를 사용하는 서버는 먼저 종료한다.

```sh
pnpm install --frozen-lockfile
NITRO_PRESET=node-server pnpm exec turbo run build --filter=@keundal/web...
pnpm --filter @keundal/web exec playwright install --with-deps chromium
node tools/a11y/check.mjs
pnpm --filter @keundal/web test:browser --project=chromium
```

`test:browser`는 `@visual` 검사를 제외한다. 공통 검사 설정은 콘솔 오류, 페이지 오류, hydration 경고, CSP 위반과 준비되지 않은 외부 요청을 실패로 처리한다. 외부 요청이 필요한 검사는 응답 fixture를 명시해야 한다. 접근성 검사는 axe의 WCAG 2 A·AA와 WCAG 2.1 A·AA 규칙을 사용한다.

웹 앱은 `features.inlineStyles: false`로 공통 CSS를 HTML과 분리해 압축 전송하고 화면 간에 캐시를 재사용한다. `tests/preview.test.ts`는 프로덕션 경로, 언어 선택과 리다이렉트뿐 아니라 연결된 CSS의 응답, Brotli 압축과 캐시 헤더를 검사한다. 스타일 적용과 레이아웃은 실제 브라우저 화면에서 확인한다.

브라우저 다운로드가 제한된 환경에서는 설치된 Chromium 경로를 명시할 수 있다. 이 설정은 자동으로 적용되지 않는다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium \
  pnpm --filter @keundal/web test:browser --project=chromium
```

CI는 고정된 `@playwright/test` 버전이 제공하는 Chromium을 설치한다. 로컬 대체 실행 파일은 CI와 버전이 다를 수 있다. Firefox와 WebKit 프로젝트도 정의되어 있지만, 이번 로컬 검증에서 두 엔진을 실행한 것은 아니다. 해당 엔진은 별도로 설치한 뒤 `--project=firefox` 또는 `--project=webkit`으로 검사한다.

## 시각적 회귀 검사

시각 검사는 기능 검사와 분리한다. 표시 설정 화면의 밝은 테마·어두운 테마를 데스크톱과 모바일 크기로 비교한다.

```sh
pnpm --filter @keundal/web test:visual --project=chromium
```

이번 로컬 기준 이미지는 Linux의 시스템 Chromium 154를 사용한다. Playwright 1.62.1이 설치하는 Chromium 151 및 CI 환경과 일치한다고 검증하지 않았으므로 CI의 기능 검사에는 포함하지 않는다. 같은 로컬 환경에서 비교하려면 실행 파일을 명시한다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium \
  pnpm --filter @keundal/web test:visual --project=chromium
```

기준 이미지 변경이 필요하면 같은 명령에 `--update-snapshots`를 추가하고 이미지 차이를 직접 검토한다. 브라우저·운영체제·글꼴이 달라 발생한 차이를 제품 변경으로 간주해서는 안 된다. CI에서 시각 검사를 필수로 적용하려면 CI와 같은 환경에서 기준 이미지를 생성하고 다시 비교해야 한다.

## 검사 목록과 제외 항목

`tools/a11y/components.json`은 공통 컴포넌트마다 실행할 검사 또는 제외 사유를 기록한다. `node tools/a11y/check.mjs`는 누락·삭제된 컴포넌트와 실행 가능한 테스트 제목의 연결을 확인한다. 이 검사는 등록된 테스트 경로가 `apps/web/tests/browser/` 아래에 있는지도 확인한다. 경로 판정은 운영체제의 경로 구분자를 슬래시로 바꾼 뒤 비교하므로 Windows에서도 정상 경로를 거부하지 않는다. 디렉터리 제한은 운영체제와 상관없이 그대로 적용한다. 목록에 등록되었다는 사실만으로 모든 상호작용 상태의 접근성을 검증한 것은 아니다.

현재 제외 항목에는 이름 변경·삭제 확인 모달, 파일 첨부·끌어놓기, 실행 중 대기열, 펼친 실행 추적, 생성된 도구 결과·출처, 일시적인 시작·로딩 화면 등이 있다. 일부 컴포넌트는 초기 화면만 검사한다. 실제 제외 사유와 최신 분류는 검사 목록을 기준으로 확인한다.

브라우저 보고서는 `apps/web/playwright-report/`, 실패 증거는 `apps/web/test-results/`에 생성된다. CI는 두 디렉터리를 아티팩트로 보관한다. 전체 단위·통합 테스트, 타입 검사와 린트는 기존 `pnpm test`, `pnpm typecheck`, `pnpm lint`로 별도 실행한다.
