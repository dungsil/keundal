# 백그라운드 작업은 부모 실행과 별도 수명으로 관리한다

## 범위

이 결정은 ADR-0003에서 제외했던 백그라운드 실행을 도입한다. 기본 `delegate_task`는 여전히 결과를 기다리며 부모 취소를 따른다. `background: true`를 지정한 호출만 `TaskService`에 작업을 등록하고 `taskId`를 즉시 반환한다. 부모의 대화, 취소 신호와 실행 추적은 백그라운드 실행에 전달하지 않는다. 기본적으로 같은 모델과 도구를 사용하며, 선택한 역할의 지침·모델·도구 허용 목록·도구 반복 한도를 적용한다. 다시 위임하지 않는다.

## 계약과 소유권

`@keundal/task`가 `TaskService`, `TaskStore`와 Cordis의 `ctx.tasks`, `ctx.taskStore`를 소유한다. `@keundal/task-memory`가 동일 프로세스 실행을 구현하며, 저장소를 주입하지 않으면 메모리에만 상태를 보관한다. Node 호스트와 브라우저 앱은 각각 SQLite·IndexedDB의 `TaskStore`를 주입한다. 공통 루프와 UI는 계약만 참조한다.

작업은 `queued → running → completed | failed | cancelled`로 전이한다. 대기 중인 작업도 바로 취소할 수 있다. 작업 서비스 전체의 동시 실행 한도는 기본 8이며 FIFO 순서로 시작한다. Node 기본 조립은 `maxActiveSubagents` 값을 이 한도에도 사용한다. 취소를 무시하는 실행이 끝나기 전에는 실행 자리를 반환하지 않는다. 늦게 도착한 성공으로 `cancelled`를 덮어쓰지 않는다.

작업 서비스가 별도의 취소 신호와 실행 소비자를 소유한다. 백그라운드 에이전트도 부모 에이전트 캐시가 아닌 작업 서비스의 범위에 생성한다. 따라서 부모 실행 종료, 부모 취소와 부모 에이전트 해제는 작업을 끝내지 않는다. 호스트 종료 시에는 미완료 작업을 `interrupted`로 저장하고 취소 신호를 전달한다. 소비자 정리와 저장이 끝난 뒤 저장소와 도구 공급자를 해제한다. 메모리 전용 구성의 종료 상태는 기존처럼 `cancelled`다.

작업 스냅숏은 부모 대화·실행 ID, 자식 대화·실행 ID, 이름, 상태, 생성·갱신 시각, 부분 응답과 오류를 보관한다. 조회는 사본을 반환하며 실행을 시작하지 않는다. 생성의 세션 커밋과 journal은 기존 `generation` 계약을 따른다.

## 조회와 취소

- 모델: `get_background_task({ taskId })`, `cancel_background_task({ taskId })`
- 인증된 HTTP: `GET /tasks`, `GET /tasks?parentThreadId=...`, `GET /tasks/:id`, `POST /tasks/:id/cancel`
- UI: 대화의 위임 카드에서 **백그라운드 작업 보기**, 또는 **설정 → 백그라운드 작업**으로 이동한다. 2초마다 상태를 갱신하고 부분 응답, 결과, 오류와 개별 취소를 표시한다. 페이지 이동은 작업을 취소하지 않는다.

## 재시작과 외부 부작용

기본 SQLite·IndexedDB 저장소는 작업 스냅숏을 별도로 저장한다. 등록과 `running` 상태를 저장한 뒤 실행 콜백을 시작하며, 스트림을 소비할 때마다 부분 응답을 저장하고 종료 상태도 확정한다. 저장 오류는 호출자에게 전달하며 저장하지 못한 새 작업을 실행하지 않는다. 기존 메모리 작업 기록은 이전할 수 없다.

작업 서비스 초기화는 저장된 `queued`, `running` 작업을 `interrupted`로 바꾸고 부분 응답과 오류를 보존한다. `completed`, `failed`, `cancelled`, `interrupted` 기록은 변경하지 않는다. 반복 복구는 상태와 갱신 시각을 다시 바꾸지 않는다. desktop 앱 종료·재실행과 모델 변경에 따른 sidecar 교체도 같은 SQLite 파일을 사용하면 기록을 유지한다. `/recover`는 기존 생성 복구만 수행하며 작업을 재등록하지 않는다.

SQLite 작업 저장소는 데이터베이스당 작업 실행 서비스 하나가 소유한다. 같은 파일에 여러 작업 실행 서비스를 동시에 연결하는 구성은 지원하지 않는다. IndexedDB는 대기·실행 작업의 Web Lock을 종료 저장과 소비자 정리까지 유지한다. 다른 탭의 복구는 잠긴 작업을 건너뛰며, 탭 종료로 잠금이 해제된 작업만 `interrupted`로 바꾼다. 브라우저의 사이트 데이터 삭제나 저장 공간 정책에 따른 데이터 유실까지 막지는 않는다.

실행 콜백은 일시적인 메모리 값이며 직렬화·복원·재호출하지 않는다. 작업 저장소에는 실행 입력이나 인증 정보를 저장하지 않는다. 작업 실패나 조회, 취소, 복구를 이유로 도구를 자동 재실행하지 않는다. 취소는 이미 발생한 파일 변경이나 외부 요청을 되돌리지 않는다. 사용자가 다시 실행하려면 부모 대화에서 새 작업을 명시적으로 요청해야 한다. 기존 실행의 체크포인트 재개 API·버튼은 제공하지 않으며, 재개 정책과 멱등성 계약은 별도 결정이 필요하다.
