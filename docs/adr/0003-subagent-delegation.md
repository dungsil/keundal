# 서브에이전트는 부모 실행 안에서 한 번만 위임한다

부모 실행은 `delegate_task` 도구로 독립된 작업을 자식 에이전트에 맡기고 결과를 기다린다. 자식은 기본적으로 부모의 모델과 도구를 쓰지만 역할별로 모델과 도구 권한을 지정할 수 있다. 부모 대화를 받지 않으며 다시 위임할 수 없다. 부모 실행마다 동시에 준비하거나 실행하는 자식 수를 `maxActiveSubagents`로 제한하며 기본값은 8이다. 한도에 도달한 호출은 자식을 만들지 않고 `rejected` 상태와 `ACTIVE_LIMIT_REACHED` 오류를 반환한다.

자식의 종료 상태는 `completed`, `failed`, `rejected`로 구분한다. 자식이 실패해도 형제와 부모 실행은 계속되고, 부모 취소는 모든 자식에게 전파한다. 결과는 마지막으로 받은 비어 있지 않은 어시스턴트 답변이며, 실패한 자식의 부분 응답은 실패 상태와 함께 보존한다. 선택적인 `label`은 80자까지 허용하고 진행 표시에 사용한다.

역할은 이름, 설명과 지침으로 정의한다. 부모 모델에는 이름과 설명을 제공하고, `delegate_task`의
선택 인자 `role`이 가리키는 지침만 서브에이전트의 시스템 메시지에 추가한다. 역할을 지정하지 않으면
기존 일반 위임을 유지한다. 역할의 선택 필드 `model`, `allowedTools`, `maxToolRounds`로 모델,
도구 허용 목록과 도구 반복 한도를 지정한다. 생략한 필드는 부모 설정을 유지하며 빈 허용 목록은
도구를 모두 금지한다. 허용 목록은 일반 도구, 스킬 도구와 지연 도구에 동일하게 적용한다.
지연 도구는 `search_tool`과 대상 도구 이름을 모두 허용해야 검색·실행할 수 있다.
허용 목록은 공급자가 제공한 도구를 제한할 뿐 새 도구나 재위임 권한을 만들지 않는다.
역할별 모델은 한도 조회, 토큰 계산, 축약 정책과 생성에 함께 적용하며 부모 설정은 바꾸지 않는다.
기존의 모델 공유 결정을 변경해 역할별 비용과 권한을 제어하되 위임 깊이와 동시 실행 한도는 유지한다.
앱은 브라우저에 저장한 역할을 실행 요청의 `state.subagentRoles`로 전달한다. 해당 목록은
`AgentConfig.subagentRoles`보다 우선하며 빈 배열로 역할을 지울 수 있다. 실행 시작 시 검증한 목록을
사용하므로 진행 중 설정을 바꿔도 이미 시작한 실행에는 영향을 주지 않는다.

## 검토한 선택

- 자식에게 후속 메시지를 보내는 안: 이번 범위에는 포함하지 않는다. 부모와 분리된 백그라운드 실행은 [ADR-0006](0006-background-tasks.md)에서 별도 계약으로 도입한다. 이 문서의 부모 취소 전파와 실행 한도는 기본 대기형 위임에 적용한다. 역할별 모델·도구 허용 목록·도구 반복 한도는 백그라운드 작업에도 적용한다.
- 재귀 위임: 동시 실행 한도와 비용 계산이 호출 트리 전체로 번지므로 사용하지 않는다. 역할별 모델 선택은 한 단계 위임 안에서 허용한다.
- 외부 CLI 공급자와 대화 복제: 현재 도구 실행 계약과 저장소 계약에 없는 수명을 요구하므로 사용하지 않는다.
