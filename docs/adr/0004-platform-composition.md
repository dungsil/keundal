# 계약과 구현 플러그인을 분리하고 앱이 조립한다

`@keundal/agent`, `tools`, `context`, `mcp`, `shell`, `transcription`, `fs`는 서비스 계약만 제공한다. 구현은 `plugin-*` 패키지에 두고, 공통 실행 루프와 축약·도구 정책은 `agent-loop`가 소유한다. 앱의 `app/platform.ts`가 실행 환경과 기본 플러그인 목록을 정한다. 계약 패키지와 공통 UI는 구현 패키지를 실행 의존성으로 가져오지 않으며, `pnpm check:boundaries`가 이를 검사한다.

필수 서비스의 구현은 런타임 매니페스트로 고른다. web은 `/keundal.plugins.json`을 기본으로 읽고 `NUXT_PUBLIC_PLUGIN_CONFIG`로 다른 URL을 지정한다. Node.js 호스트와 desktop은 `KEUNDAL_PLUGIN_CONFIG`, 앱 데이터 디렉터리, 현재 디렉터리 순서로 설정 파일을 찾는다. 배포 설정이나 모듈이 잘못되면 기본 구성으로 대체하지 않고 시작을 거부한다.

선택 기능은 **설정 → 큰달 플러그인**에서 활성화·비활성화한다. web은 앱에 함께 패키징한 기능 모듈만 제공한다. desktop은 여기에 npm·JSR 패키지와 로컬 ZIP·경로의 큰달 플러그인을 추가할 수 있다. 외부 설치는 배포 매니페스트와 분리하며, 이전의 외부 모듈 선택을 자동으로 가져오지는 않는다. web은 실행 기능의 선택을 바로 반영하고 desktop은 선택 변경 후 sidecar를 다시 시작한다. 변경 전에는 진행 중인 응답을 중단하며, 비활성화는 사용자 데이터를 삭제하지 않는다.

desktop은 npm을 앱에 포함하고 설치 스크립트를 실행하지 않는다. 패키지와 ZIP은 전용 디렉터리에 의존성과 함께 설치하며, JavaScript 파일 경로는 원본을 참조한다. 외부 코드는 설치 직후에는 실행하지 않고, 사용자가 활성화할 때 기본 내보내기를 Cordis 플러그인으로 등록한다. 활성화 오류는 관리 화면에 표시하고 이전 선택을 복구한다. 플러그인은 호스트 권한으로 실행되므로 설치 화면에서 신뢰 여부를 확인한다. 삭제할 때는 관리하는 복사본만 지우고 원본 경로와 대화 기록은 유지한다.

선택 기능의 목록은 배포 매니페스트와 분리한다. 번들 목록에는 필수 서비스인 LLM·저장소·에이전트와 선택 기능인 스킬·MCP·날씨·차트 도구를 표시하고, desktop에서는 사용자가 설치한 외부 항목을 추가한다. 필수 서비스는 끌 수 없다. `ui-*`는 목록이나 별도 스위치를 제공하지 않는다. `@keundal/plugin-skill`은 `@keundal/ui-skill`, `@keundal/plugin-mcp-client`는 `@keundal/ui-mcp`의 수명을 결정한다. 스킬·MCP를 끄면 대응하는 화면의 Cordis 등록 범위와 탐색 항목도 해제하며, 다시 켜면 함께 등록한다. 나머지 UI는 항상 등록하고 Nuxt 레이어도 빌드에 유지한다.

`@keundal/ui-tool`은 `@keundal/ui-chat`처럼 공유 메시지 표시를 담당하므로 항상 등록한다. 날씨·차트뿐 아니라 `delegate_task`, `skill`, `web_search`, `google_search` 결과도 표시한다. `@keundal/plugin-tool-chat`을 끄면 이후 실행 목록에서 날씨·차트 도구를 제외하지만, 기존 대화 기록과 다른 선택 기능의 결과를 표시하는 UI는 해제하지 않는다.

선택의 저장은 실행 방식의 관리자가 맡는다. web의 `BrowserRuntimePluginManager`는 기존 `keundal:bundled-plugins` localStorage를 사용하고 desktop은 기존 네이티브 저장소를 사용한다. 이전 `keundal-ui-plugins` 쿠키는 읽거나 선택에 반영하지 않는다. 서버 렌더링과 최초 하이드레이션은 기본 UI를 등록하며, 앱이 마운트된 뒤 실제 실행 방식의 선택과 화면을 동기화한다.

배포 설정을 덮어쓰는 관리 API는 제공하지 않는다. 선택 기능의 활성화 오류는 진단으로 표시하며, 관리 화면에 접근할 수 있도록 앱 시작은 유지한다. 원격 서버의 실행 기능은 해당 호스트에서 관리한다. `platform.runtimePlugins`가 없는 원격 연결에서는 기능 관리자를 노출하지 않고 관리 화면에 사용할 수 없음을 표시한다. 기본 UI는 유지하며, 로컬 UI만 별도로 끄고 켜는 기능은 제공하지 않는다.

저장소와 `session`의 수명은 LLM에 종속시키지 않는다. LLM을 교체하면 `generation`과 에이전트만 다시 구성하고 기존 대화와 journal은 유지한다. 플러그인 전체를 해제할 때는 진행 중인 생성을 먼저 정리한 뒤 소유한 저장소를 닫는다.

## 검토한 선택

- 앱의 TypeScript 조립 코드만 두는 안: 구현을 바꿀 때마다 앱을 다시 빌드해야 하므로 사용하지 않는다.
- YAML 로더: 기존 JSON 형식과 별도 설정 형식을 유지할 이유가 없어 사용하지 않는다.
- 배포 매니페스트를 UI에서 직접 수정하는 안: 필수 서비스와 사용자의 선택 기능을 같은 수명으로 관리하게 되므로 사용하지 않는다.
- UI를 별도로 선택하고 쿠키에 저장하는 안: 실행 기능과 화면이 서로 다른 상태가 될 수 있으므로 사용하지 않는다.
- web의 외부 모듈 설치: Node.js 패키지 설치와 로컬 경로 접근은 desktop에서만 제공한다.
- MCP 도구 조립만을 위한 별도 패키지: 독립 소비자가 없으므로 추가하지 않는다.

플랫폼별 구현 선택은 `docs/plugin-composition.md`에 정리한다.
