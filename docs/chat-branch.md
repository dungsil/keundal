# 대화 분기

메시지의 **새 대화로 분기** 버튼은 선택한 메시지까지 복사한 새 대화를 만들고 그 대화로 이동합니다. 원래 대화는 바꾸지 않습니다. 편집과 재생성처럼 뒤쪽 메시지를 지우지 않고 다른 질문이나 모델을 시도할 때 사용합니다.

## 계약

`ChatStoreLike.branch(sourceId, messageId, newId)`는 새 `LocalChat`을 돌려줍니다. `@keundal/plugin-chat-local`의 `ChatStore`와 `@keundal/plugin-chat-remote`의 `RemoteChatStore`(데스크톱은 이를 상속)가 구현하며, 복사 규칙은 `@keundal/chat`의 `branchChat()` 하나에 둡니다.

- 원래 대화를 읽고 새 `threadId`에 한 번만 저장합니다. 저장은 `SessionService`의 `get()`과 `commit()`, 원격에서는 기존 `GET`·`PUT /threads/:id`만 씁니다. 새 라우트와 저장소 스키마 변경은 없습니다.
- `newId`가 이미 있으면 `create()`처럼 `Chat already exists`로 거부합니다. 원래 대화가 없으면 `Chat not found`, 선택한 메시지가 없거나 사용자·어시스턴트 메시지가 아니면 `Invalid message`로 거부하며 새 대화를 남기지 않습니다.
- 대화 안에서 실행 중이어도 분기할 수 있습니다. 원래 대화를 바꾸지 않으므로 실행과 겹치지 않습니다. 실행 중에 쌓인 메모리의 대기 메시지와 지시는 복사하지 않습니다.
- 편집·재생성의 `truncate()`는 바뀌지 않습니다.

## 복사 규칙

| 항목                    | 규칙                                                                                                                              | 이유                                                                                                                                                      |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `messages`              | 선택한 메시지까지 깊은 복사합니다. 선택한 메시지 바로 뒤에 `metadata.steeredRunId`가 있는 지시 메시지가 이어지면 함께 복사합니다. | 반영된 지시는 앞선 어시스턴트 기록에 들어 있어, 떼어 놓으면 화면과 모델 입력이 어긋납니다.                                                                |
| `votes`                 | 복사한 메시지에 달린 투표만 `chatId`를 새 대화로 바꿔 유지합니다.                                                                 | 같은 응답에 대한 평가는 분기 뒤에도 유효합니다.                                                                                                           |
| `queue`                 | 복사하지 않습니다.                                                                                                                | 대기 메시지는 원래 대화에서 보낼 메시지입니다.                                                                                                            |
| `pendingRunId`          | 복사하지 않습니다.                                                                                                                | 진행 중인 실행은 원래 대화의 것입니다.                                                                                                                    |
| `metadata.steeredRunId` | 복사한 메시지에서는 그대로 둡니다.                                                                                                | 표시용 표식이며 모델 입력은 어시스턴트 기록이 조립합니다.                                                                                                 |
| `title`                 | 그대로 복사합니다. 제목이 없으면 첫 응답 때 새로 만듭니다.                                                                        | 분기 직후에도 목록에서 같은 주제로 보입니다.                                                                                                              |
| `createdAt`             | 분기한 시각입니다.                                                                                                                | 목록이 최신 대화를 앞에 두므로 분기한 대화가 맨 위에 옵니다.                                                                                              |
| `model`                 | 그대로 복사합니다.                                                                                                                | 이어서 같은 모델로 응답합니다.                                                                                                                            |
| `started`               | 항상 `true`입니다.                                                                                                                | 새 대화를 열 때 응답이 자동으로 시작되지 않게 합니다. 사용자 메시지에서 분기하면 질문으로 끝나는 대화가 되며, 사용자가 이어서 보내거나 질문을 수정합니다. |
| `visibility`, `isOwner` | `private`, `true`입니다.                                                                                                          | 새 대화의 기본값입니다.                                                                                                                                   |

## 실행 추적

복사한 어시스턴트 메시지의 `id`는 원래 실행의 `runId`로 그대로 둡니다. 실행 journal은 복제하지 않습니다.

- 원래 대화가 남아 있으면 분기한 대화의 실행 추적 패널이 `getRun(runId)`로 원래 실행을 보여 줍니다.
- 원래 대화를 지우면 `session.delete()`가 실행과 journal을 함께 지우므로 `getRun()`이 `undefined`를 돌려줍니다(메모리·IndexedDB·SQLite·원격 호스트 모두 같습니다). 패널은 "실행 정보를 사용할 수 없습니다"를 표시하고, 대화 본문과 투표는 그대로 남습니다.
- journal을 새 `runId`로 복제하는 방식은 저장 용량을 늘리고, 실행 기록을 별도로 두 번 쓰지 않는다는 [ADR 0002](adr/0002-trace-journal-metadata.md)의 방향과 맞지 않아 채택하지 않았습니다.

## 제한

- 분기한 대화에서 원래 대화로 돌아가는 링크나 목록의 관계 표시는 없습니다. 제목을 그대로 복사하므로 필요하면 이름을 바꿉니다.
- 한 대화 안에서 갈래를 오가는 트리 화면은 제공하지 않습니다.
