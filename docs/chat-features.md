# 공용 채팅 화면과 기능

web과 desktop은 각 앱의 `nuxt.config.ts`와 `app/ui-plugins.ts`에서 UI 기능을 직접 조립합니다. 시작 화면·전역 메타데이터·본문 틀은 `@keundal/ui-shell`, 사이드바는 `@keundal/ui-sidebar`가 담당합니다. 대화·설정·모델 목록·스킬 화면도 각 `@keundal/ui-*` 패키지가 슬롯에 등록합니다. 구조와 슬롯은 [UI 플러그인 문서](ui-plugins.md)를 참고합니다.

앱은 필요한 UI 패키지를 Nuxt `extends`에 나열하고, 먼저 실행되는 `chat-platform` Nuxt 플러그인에서 `@keundal/chat/platform`의 `ChatPlatform`을 제공합니다. `app/plugins/ui.ts`는 `@keundal/ui-runtime/nuxt`의 `createUIPlugin(catalog)`를 사용합니다. 이 초기화 함수는 IndexedDB, LLM SDK, Tauri, sidecar 구현을 직접 가져오지 않습니다.

`runtimeConfig.public.chatCapabilities`는 보안 저장소 설명과 로컬 스킬 설정의 표시 여부를 정합니다. 구현과 실행 수명은 각 앱의 `app/platform.ts`에서 관리합니다. 자세한 경계와 교체 방법은 [플러그인 조립 문서](plugin-composition.md)를 참고합니다.

## 시작 화면

시작 화면은 앱과 저장된 테마 설정이 준비되면 사라집니다. 웹 글꼴 다운로드가 끝날 때까지 입력을 막지 않습니다. Pretendard의 `font-display: swap` 설정은 유지하므로 글꼴을 불러오는 동안 대체 글꼴을 표시합니다.

## 긴 제목 표시

공유 대화의 상단 제목을 누르면 팝오버에서 전체 제목을 확인할 수 있습니다.
키보드에서는 제목 버튼에 초점을 두고 Enter 또는 Space로 열며, Escape로 닫습니다.
차트 제목은 화면 폭에 맞춰 줄바꿈하여 전체 내용을 표시합니다.

## 설정 메뉴

설정 메뉴에서 **에이전트 플러그인**, **스킬**, **MCP 서버**를 관리합니다.
기존 설정 URL과 설정을 저장하고 실행하는 방식은 유지합니다.

## 접근성

전역 레이아웃은 첫 초점 대상으로 **본문으로 건너뛰기** 링크를 두고, `main#main-content`를 노출합니다.
경로를 이동하면 사이드바를 닫고 `main`으로 초점을 옮기며, 화면 제목에는 대화 제목이나 설정 섹션 이름을 함께 표시합니다.

대화 목록은 대화 링크와 이름 변경·삭제 버튼을 형제 요소로 분리합니다.
아이콘만 표시하는 버튼과 접힌 사이드바 항목에는 `aria-label`로 이름을 붙입니다.
대화 메시지 영역은 `role="log"`와 `aria-busy`로 응답 진행 상태를 알립니다.

입력 오류는 제출할 때 검사합니다.
실패한 입력란에는 `aria-invalid`와 `aria-describedby`를 지정하고 해당 입력란으로 초점을 옮깁니다.
첨부 이미지 확대는 `UModal`로 열며, Esc로 닫으면 원래 버튼으로 초점이 돌아갑니다.

움직임은 `motion-safe` 변형과 `prefers-reduced-motion: reduce` 조건에서만 실행합니다.
고정된 상단 바와 입력창 아래로 초점이 가려지지 않도록 스크롤 여백을 지정합니다.

## MCP 서버

**설정 → 에이전트 플러그인 → MCP 서버**에서 서버를 추가·수정·삭제합니다. 서버 이름, 연결 주소 또는 실행 명령, 인증 정보와 권한을 입력합니다. 허용할 도구 이름과 리소스 URI는 한 줄에 하나씩 입력합니다. `*`는 전체 허용이며, 빈 목록은 접근을 차단합니다. 인자에는 JSON 배열을, HTTP 헤더와 환경 변수에는 JSON 객체를 사용합니다.

- 웹은 Streamable HTTP를 지원하며 브라우저에서 서버에 직접 연결합니다. 서버가 앱 origin의 CORS 요청과 MCP 헤더를 허용해야 합니다. HTTPS 앱에서는 HTTPS 서버를 사용합니다. 인증 정보를 포함한 설정은 브라우저 localStorage에 저장합니다.
- 데스크톱은 Streamable HTTP와 stdio를 지원합니다. 로컬 호스트가 서버에 연결하며, stdio 명령은 셸을 거치지 않고 실행합니다. 실행할 명령은 설치되어 있어야 합니다. 설정은 OS 보안 저장소의 `com.keundal.desktop` 서비스, `mcp-settings` 항목에 저장하며 브라우저 저장소로 대체하지 않습니다. 신뢰하는 서버만 등록합니다.
- 원격 에이전트를 사용하는 웹에서는 호스트 관리자가 `KEUNDAL_MCP_SERVERS`를 설정합니다. 브라우저 설정으로 원격 호스트의 실행 명령을 변경하지 않습니다.

저장하면 진행 중인 응답을 중단하며 데스크톱은 로컬 호스트를 다시 시작합니다. 서버 연결과 도구 조회는 다음 응답을 시작할 때 수행하므로, 설정 저장 성공은 서버 연결 성공을 뜻하지 않습니다. 저장 전에 연결을 확인하려면 아래 **연결 확인**을 사용합니다. 연결이나 도구 조회가 실패하면 해당 응답에 오류를 표시합니다. 설정을 수정하거나 다시 요청하면 연결을 다시 시도할 수 있습니다. 제목 생성에는 MCP 도구를 사용하지 않습니다.

응답을 시작할 때 서버의 도구 목록을 다시 조회하고, 허용한 도구와 리소스만 에이전트에 제공합니다. 취소는 MCP 요청에 전달하며, 호스트 종료나 설정 교체 시 연결을 정리합니다. 데스크톱은 종료 제어 파이프를 닫아 호스트가 MCP 자원을 정리할 시간을 주고, 5초 안에 종료되지 않으면 호스트를 강제로 종료합니다. OAuth 로그인, 레거시 SSE, MCP prompts는 지원하지 않습니다.

### 연결 확인

**연결 확인**은 폼에 입력한 값으로 서버에 임시로 연결합니다. 저장하지 않은 값도 확인할 수 있으며, 저장된 설정과 진행 중인 응답에는 영향을 주지 않습니다. 서버가 알려 주는 도구 이름과 리소스 개수를 조회한 뒤 연결을 닫습니다. 도구는 실행하지 않습니다.

- 목록에서 도구를 선택하면 **허용할 도구**에 이름을 추가합니다. 이름을 직접 입력하는 방법도 그대로 사용합니다. `*`로 전체를 허용한 상태에서 도구 하나를 해제하면 나머지 도구를 이름으로 나열합니다. 허용 목록에 있지만 서버가 알려 주지 않은 이름은 경고로 표시합니다.
- 확인에 실패해도 저장은 막지 않습니다. 브라우저는 CORS 거부와 네트워크 오류를 구분해 주지 않으므로, 오류 문구에 주소와 서버 실행 여부, CORS 허용 여부를 함께 안내합니다. 시간 초과는 따로 표시하고, 다른 오류는 상세 내용에 오류 메시지를 덧붙입니다.
- **요청 제한 시간**은 연결과 조회를 합친 확인 전체에 적용합니다. 시간이 지났을 때, **확인 취소**를 눌렀을 때, 연결 값을 바꿨을 때, 화면을 떠났을 때 연결을 닫습니다. 결과는 확인한 시점의 서버 상태이며, 서버가 나중에 추가한 도구는 허용 목록에 넣기 전에는 에이전트에 제공하지 않습니다.
- 데스크톱은 Streamable HTTP 서버만 확인합니다. 확인은 앱 창에서 요청하므로 서버가 앱 origin의 CORS를 허용해야 하며, 대화에 응답하는 로컬 호스트를 거치지 않습니다. 저장하지 않은 설정을 로컬 호스트의 HTTP 요청으로 받지 않기 때문입니다. stdio 명령은 확인하지 않고 실행하지도 않습니다.
- 원격 에이전트를 사용하는 웹에서는 설정 폼을 표시하지 않으므로 연결 확인도 제공하지 않습니다.

## 서브에이전트

브라우저와 호스트 실행에서 모델은 `delegate_task`로 독립된 작업을 위임할 수 있습니다.
같은 응답에서 여러 작업을 위임하면 병렬로 실행합니다. 대화 화면은 각 작업의 대기, 실행,
완료, 실패 또는 중단 상태를 표시하며, 항목을 펼치면 작업 지침과 최종 답변을 볼 수 있습니다.
부모 응답을 중단하면 실행 중인 자식도 중단합니다. 브라우저 실행은
`createKeundalChat(context, model, { subagents: false }, mountAgent)`로 비활성화할 수 있습니다.

작업에 `label`이 있으면 그 이름을 표시합니다. 실패한 자식의 오류와 부분 응답은 완료 결과와 구분하여
표시하며, 진행 이벤트 없이 저장된 도구 결과만 읽어도 성공과 실패를 구분합니다.

**설정 → 서브에이전트**에서 역할의 이름, 설명과 지침을 추가·수정·삭제하고 **저장**을 누릅니다.
역할은 브라우저 저장소에 보관하며 다음 응답부터 브라우저와 호스트 실행에 전달합니다.
모델은 이름과 설명을 보고 `delegate_task`의 `role`로 선택하며, 선택한 역할의 지침은 서브에이전트에만
시스템 메시지로 전달합니다. 역할을 선택하지 않은 일반 위임도 계속 사용할 수 있습니다.
역할별 모델이나 도구 권한을 바꾸지는 않습니다. 호스트에서 서브에이전트를 끈 경우 역할을 저장해도
위임 도구가 활성화되지는 않습니다.

## 실행 추적

각 어시스턴트 응답에는 연결된 `runId`의 실행 추적 패널이 있습니다. 패널을 펼치면 실행 단계의 트리와 타임라인, 토큰·캐시·비용·시간 집계를 확인할 수 있습니다.

`Simple`은 주요 단계 정보만 표시합니다. `Full`은 모델, 상태, 사용량 출처, 첫 토큰 응답 시간과 안전한 오류 분류를 표시합니다. Journal은 패널을 열 때만 불러오며, 최대 20개 응답과 실행당 200개 단계만 화면에 표시합니다.

실행 중에는 AG-UI로 받은 Trace를 즉시 표시합니다. 열린 패널은 1.2초 간격으로 저장 기록과 종료 상태도 확인합니다. 저장소 상태가 `failed`, `cancelled` 또는 `interrupted`이면 끝나지 않은 단계에 반영하며, 분리된 배경 작업은 미확정으로 표시합니다. 추적 메타데이터가 없는 이전 실행에는 저널 이벤트 수를 대신 표시합니다.
