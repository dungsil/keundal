# 데이터 백업·복원

**설정 → 백업·복원**(`/settings/data`)에서 JSON 파일을 다운로드하고 다른 기기에서 복원한다.
web의 IndexedDB와 desktop의 SQLite는 같은 포맷을 사용한다. 자동 동기화나 충돌 병합은 하지 않는다.

## 사용 방법

1. 원래 기기에서 진행 중인 응답과 백그라운드 작업을 끝낸 뒤 **백업 다운로드**를 누른다.
2. 새 기기에서 **백업 파일 선택**으로 파일을 연다. 만든 날짜와 대화·생성 기록·프리셋·스킬 개수를 확인한다.
3. 신뢰하는 파일인지 확인하고 사용자 설정 교체에 동의한 뒤 **백업 복원**을 누른다.
4. **앱 새로고침**을 누르고 LLM의 API 키와 필요한 요청 헤더를 다시 입력한다. MCP 인증 정보와 권한도 확인한다.

복원은 기존 대화를 지우지 않고 새 대화를 추가한다. 대화 ID나 생성 ID가 하나라도 겹치면 전체 복원을 거부한다.
같은 파일을 두 번 복원해도 중복 대화를 만들거나 기존 기록을 덮어쓰지 않는다. 충돌한 기록을 자동으로 이름 변경하거나 병합하지 않는다.

사용자 설정은 백업 값으로 교체한다. **저장된 API 키도 지우므로 기존 기기에 복원할 때 주의한다.**
데이터를 저장하지 못하면 앞서 바꾼 설정을 되돌린다. 되돌리기도 실패하면 별도 오류를 표시하며 설정 확인을 요청한다.
설정 저장소와 대화 저장소를 아우르는 분산 트랜잭션은 아니므로 복원 도중 앱을 강제 종료하지 않는다.

## 포함 범위

| 데이터          | 처리                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| 대화            | ID, revision, 제목, 날짜, 메시지, 이미지 data URL, 투표, 대기 메시지와 세션 상태를 보존한다                          |
| 생성 기록       | 요청, 종료 상태, 생성 메시지, journal과 실행 추적을 보존한다. 실행을 다시 시작하지 않는다                            |
| 프롬프트 프리셋 | 선택한 프리셋과 블록·변수를 보존한다. 이전 단일 사용자 지침도 프리셋으로 옮긴다                                      |
| 스킬            | 관리 스킬과 로컬 `SKILL.md`의 정의를 관리 스킬로 옮긴다. 기기별 경로는 옮기지 않는다                                 |
| 사용자 설정     | LLM 공급자 이름·주소·모델, 기본·선택·제목 모델, 언어, 테마, 검색·추론 설정, 실행 예산과 서브에이전트 역할을 보존한다 |
| 선택 기능       | 대상 기기에 이미 포함된 번들 항목만 선택을 적용한다. 없는 항목은 성공 화면에서 알린다                                |
| MCP             | HTTP 서버 설정을 옮기되 인증 헤더·URL 쿼리·권한은 비운다. stdio 명령은 옮기지 않는다                                 |

복원한 대화는 자동 응답 시작 상태와 `pendingRunId`를 해제한다. 원래 기기의 실행 소유권이나 잠금은 옮기지 않는다.
로컬 스킬과 관리 스킬의 이름이 겹치면 관리 스킬을 우선하며, 로컬 스킬의 폴더 구조나 부속 파일은 옮기지 않는다.
외부 큰달 플러그인의 설치 파일, 에이전트 플러그인 묶음, 배포 매니페스트와 환경 변수는 포함하지 않는다.
새 기기에서 필요한 코드를 직접 설치하고 신뢰 여부를 확인한다. 백그라운드 작업의 상태·관계 레코드는 포함하지 않는다.
작업이 만든 대화와 생성 기록은 보존하지만 작업 목록이나 실행 소유권은 옮기지 않는다.

백업 파일은 **암호화하지 않는다**. 설정의 API 키를 제외해도 대화, 프롬프트, 스킬, 도구 결과와 생성 요청에는
민감한 내용이 들어갈 수 있다. 파일은 안전한 장소에 보관하고 신뢰할 수 없는 파일은 복원하지 않는다.

## 포맷과 저장소 계약

최상위 필드는 `format: "keundal-backup"`, `version: 1`, `createdAt`, `history`, `settings`다.
지원하지 않는 버전과 손상된 참조·중복 ID·불연속 journal은 쓰기 전에 거부한다. 파일 한도는 UTF-8 기준 64 MiB다.
HTTP 호스트가 더 작은 `maxRequestBodyBytes`를 지정했다면 그 한도를 우선한다.

`@keundal/backup`은 `HistoryBackup`과 Cordis의 `ctx.backup` 계약을 소유한다.
IndexedDB·SQLite·메모리 저장소 플러그인은 LLM 등록과 독립적으로 이 서비스를 제공한다.
`export()`는 일관된 세션·생성 스냅샷을 반환하고 `import()`는 대화와 모든 실행·journal을 하나의 저장소 트랜잭션으로 추가한다.
원본이나 대상에 `running` 기록이 있으면 거부하며 ID 충돌 검사는 쓰기 트랜잭션 안에서도 다시 수행한다.

`@keundal/chat`은 버전 포맷, 화면의 대화 상태 검증과 플랫폼 설정 이전을 소유한다.
`ChatStoreLike.backup`은 선택 계약이므로 이를 제공하지 않는 사용자 저장소에서는 오류를 표시한다.
desktop은 인증된 호스트의 `GET /backup`, `POST /backup`을 사용한다. 일반 원격 호스트의 파일·환경 설정은 변경하지 않는다.
새 기능 패키지나 저장소 구현을 추가하면 같은 계약과 버전 검증을 유지한다.
